第一轮解决了「接入面」：系统打开方式、外部文件直开、基础语法高亮、README 版本对齐。这一轮把 MT 的 assets/ 与 Web 管理器代码再挖了一层，得到两个判断：

  • 本地端功能几乎不缺。回收站、书签、批量重命名、隐藏文件、排序、媒体播放、十六进制、ARSC 翻译、APKS、Shizuku/Root、WebDAV/FTP/SFTP/SMB/S3、Termux、GPG 都已具备；targetSdk 34 与 V1/V2/V3 签名反而比 MT（targetSdk 30）更现代。
  • 剩余差距集中在三处：远程端只读、预览与国际化、编辑器细节。本轮把编辑器细节里三个可直接修的补齐；远程端涉及安全模型，国际化与预览属于独立迭代，均列入清单而非擅自改动。

二、结论先行

最值得做的下一件事是把 LocalService 从「配对码 + 只读」升级为完整读写 Web 管理器 —— 这是与 MT 唯一的结构性功能差距。但它会把写操作暴露到局域网，属于安全模型变更，需要你先拍板。其次是 i18n 外置语言包与 Markdown/KaTeX 预览，两者都不涉及权限变化，但改动面较大，适合单独一轮。
本轮为什么只改了编辑器：字体、语法映射、查找替换都是纯前端 / 资源层改动，不改变任何权限、不新增 Activity、不触碰网络服务，风险最低且能立即验证。i18n 需要替换成百上千处硬编码文案，Markdown 预览需要新增页面与 KaTeX 字体资源，混进同一轮会让回归难以定位。

四、本轮已落地的 3 项改动

① 打包等宽字体，消除跨 ROM 的代码对齐漂移

app/src/main/assets/style.css · fonts/JetBrainsMono-Regular.woff2 · licenses/JetBrains-Mono-OFL.txt · README.md

项目 CSS 里 .CodeMirror 请求 'Droid Sans Mono'，--mono 直接用 monospace，但 assets/fonts/ 里只有 Public Sans（比例字体）。结果是编辑器、十六进制视图、终端、编译日志的对齐完全依赖系统 fallback，不同 ROM 上中文与 ASCII 混排会错列。MT 内置 Mono.ttf 正是为此。

现打包 21,168 字节的 JetBrains Mono woff2（SIL OFL 1.1），用 @font-face 加载并让 --mono 指向它；Droid Sans Mono 保留为回退。许可文本放入 licenses/，README 记录来源。纯离线，无运行时网络请求。

② 语法覆盖 51 → 84 条，对齐 MT 的常见语言

app.html（+15 个 script）· vendor/ 下 15 个模式文件 · app.js（映射 + 文件名特判 + textExtensions）· README.md

新增 Lua、PHP、Ruby、Swift、Dart、Groovy、TOML、PowerShell、VB、LaTeX、CMake、Sass、TCL、GNU as、Brainfuck 共 15 个 CodeMirror 5.65.16 模式（合计约 115 KB），扩展名映射从 51 增至 84 条；CMakeLists.txt 按文件名特判为 CMake。同步扩展 textExtensions，让新语言显示文本图标而不是通用文件图标。

过程中修掉一处回归：最初把 xml 也加进了 textExtensions，导致 fileType('layout.xml') 从 xml 变成 text，会绕过 XML 的「反编译 / 字符串池」入口。已收窄为只追加新语言后缀，不触碰 xml/java/smali 等原有分类。所有映射都验证过 CodeMirror.getMode() 运行时可用，未注册的模式仍安全回退纯文本。

③ 查找 / 替换支持正则、大小写开关、匹配计数与捕获组

app.js（findText / replaceText 及 5 个共享 helper）· style.css（.findOpts）

原有实现：搜索固定 caseFold:true（不区分大小写），替换固定 false（区分大小写），两者行为不一致；都不支持正则，替换无计数，无效输入静默无反应。MT 的远程管理器明确有「正则表达式 / 全部替换 / 展开替换 / 折叠替换」。

现在两个对话框共享 正则表达式 / 区分大小写 开关并记忆选择；搜索显示「第 N 行 · 共 M 处匹配」（带缓存，避免每次翻页全量扫描）；正则替换支持 $1–$9 与 $& 捕获组引用；无效正则会提示具体错误而不是空操作。底层复用项目早已打包的 searchcursor.js，未引入新依赖。
