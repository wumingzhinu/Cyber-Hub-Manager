r5 版本核对卡

针对刚发来的「提权诊断」截图 · 2026-11-08
结论：这张诊断来自旧版 APK，不是 r5（build-56）
设备上运行的仍是 r4 / build-55 或更早版本，所以 shizukuRunning: false 属预期——旧版 Manifest 没有 API_V23 声明，Shizuku 服务端不会推 binder。r5 的修复已经过 CI 与 AXML 元素树校验，是正确的，本轮无需再改代码。

三条判断依据

证据说明
文件哈希相同本次截图与上一轮那张 SHA256 完全一致（1280b570…8d32761），是同一张图重发，不是装了新版后重新截的。
缺 4 个新字段r5 的诊断弹窗会打印 apiV23Declared、v3SupportDeclared、binderSeen、shizukuUid 四行；截图里一行都没有。
npErr 是旧文案截图为「Shizuku 服务未启动或 binder 未送达…请确认…若仍连不上，请…停止并重新启动服务」；r5 会改成「客户端未声明 API_V23 权限（根因）」或带「在 Shizuku「应用管理」里允许本应用」的新措辞。旧文案在 r5 APK 内计数为 0。

装好 r5 后，诊断应该长这样

rootGranted: false
rootAvailable: false
shizukuInstalled: true
shizukuProviderRegistered: true
apiV23Declared（已声明API_V23权限）: true      ← 新增
v3SupportDeclared（v3客户端标记）: true        ← 新增
shizukuRunning（服务运行中）: true             ← 目标
binderSeen（曾收到binder）: true               ← 新增
shizukuGranted（已授权）: false → 点申请后 true
shizukuVersion: 13
shizukuUid（0=root / 2000=adb）: 2000          ← 新增
elevatedId: uid=2000(shell) ...
rootListCount: 正数

只要诊断里出现 apiV23Declared 这一行，就说明 r5 已经装对了；看不到就还是旧包（或从最近任务没彻底划掉，WebView 没重新加载）。

请按这个顺序做一遍

  1. 安装 Cyber-Hub-Manager-0.1.59-r5.apk（Release build-56）。签名证书未变，可直接覆盖安装，不用卸载。
  2. 从最近任务里把本应用彻底划掉（只按返回键不会重新加载页面）。
  3. 打开 Shizuku 应用：停止服务 → 重新启动服务，并在「应用管理」里允许本应用。服务端用 UID 列表记住已推送对象，覆盖安装后必须重启才会重推 binder。
  4. 重新打开本应用 → 设置 → 启动 → 诊断，把新截图发我。

不依赖 Shizuku 的兜底方案

如果只是要访问 Android/data 等受限目录，用 设置 → 启动 → 授权 Android/data（系统文件访问框架 SAF）即可，不需要 Root 也不需要 Shizuku。Shizuku/Root 是为了浏览更上层的 /data 等目录。
