「代码全是黑色」根因定位与修复 · 提交 8369fea · CI run 42472596502

结论：不是配色问题，是资源被 404 拦截

既不是没装新 APK，也不是 CSS 没写。Java 层 MainActivity.localAsset() 里有一份只放行 9 个文件的固定白名单：

Arrays.asList("app.html","app.js","boot.js","style.css","vendor/codemirror.js","vendor/codemirror.css","vendor/clike.js","vendor/xml.js","vendor/searchcursor.js")

前三轮新增的 30 个 CodeMirror 语法模式、lang/packs.js、vendor/katex/*、JetBrains Mono 字体、ninepatch.js、markdown-preview.js 等全部返回 404。因此真机上 python.js 从未加载，CodeMirror.modes.python 不存在，editorModeFor() 返回 null，所有 token 不着色。同理，语言切换、KaTeX 预览、九宫格编辑等新功能此前也不可用。

证据链

浏览器渲染用真实 Chromium 加载同款 CSS + CodeMirror + python mode，浅色主题下关键字紫 rgb(130,80,223)、字符串绿 rgb(10,123,69)、注释灰、数字棕 —— 前端代码本身完全正常
打包核对APK 内 33 个 vendor/*.js 一个不少，python.js 存在，app.html 引用的脚本无缺失
新旧对比旧版 app.html 只加载 4 个脚本；新版加载 38 个，但 Java 白名单仍只放行 9 个 → 新脚本全部 404
CI 盲区CI 只跑 JS 语法与 JVM 冒烟，不启动真机 WebView，所以这个拦截一直没被自动测试发现

修复内容（5 个文件，+70 / −6）

资源放行isStaticAsset() 安全目录放行：拒绝 .. / 绝对路径 / % / : / 反斜杠；显式排除 development-signing.p12 与 jar/dex/apk/p12/jks/keystore；仅允许静态资源扩展名。新增 assetMime() 返回正确 MIME（含 font/woff2）
缓存WebSettings.LOAD_NO_CACHE + 升级后清一次 WebView 缓存（assetEpoch=4），避免旧 app.html 被复用
编码字段DataEngine.read() 返回 encoding
可见诊断编辑器信息栏显示「编码 · 语法模式 · 构建标记 r4」，一眼可确认资源是否已更新
编辑器增强当前行高亮 cm-activeLine；补齐浅色 / 深色主题下 def、builtin、variable、type、property、operator、meta、tag、attribute 等 token 配色
