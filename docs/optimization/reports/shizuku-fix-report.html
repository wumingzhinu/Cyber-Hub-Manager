关键矛盾：接入组件已注册、Shizuku 已安装，服务端却在「运行中」被判为 false。此前几版把原因归到「服务未启动」或「binder 只在进程启动时送达（时序）」，都不成立。

二、根因（官方源码 + MT 对照）

Shizuku 服务端 server/src/main/java/rikka/shizuku/server/BinderSender.java 的 sendBinder() 在应用进程启动 / 回到前台时决定是否推送 binder，筛选逻辑是：

private static final String PERMISSION = "moe.shizuku.manager.permission.API_V23";

PackageInfo pi = PackageManagerApis.getPackageInfoNoThrow(
        packageName, PackageManager.GET_PERMISSIONS, userId);
if (pi == null || pi.requestedPermissions == null)
    continue;                                    // 没有任何权限声明 → 直接跳过

if (ArraysKt.contains(pi.requestedPermissions, PERMISSION_MANAGER)) { ... }
else if (ArraysKt.contains(pi.requestedPermissions, PERMISSION)) {
    ShizukuService.sendBinderToUserApp(sShizukuService, packageName, userId);
    return;                                      // 只有声明了 API_V23 才推
}

也就是说 Shizuku 只向 Manifest 里声明了 API_V23 权限的客户端推送 binder，与服务是否运行、provider 是否注册无关。

MT 管理器 2.26.11 的清单明确同时声明了三项：

<uses-permission android:name="moe.shizuku.manager.permission.API_V23" />
<meta-data android:name="moe.shizuku.client.V3_SUPPORT" android:value="true" />
<provider android:name="…" android:authorities="bin.mt.plus.shizuku"
          android:exported="true" android:multiprocess="false"
          android:permission="android.permission.INTERACT_ACROSS_USERS_FULL" />

本项目用 aapt2 直接打包、没有 Gradle manifest merger：官方 dev.rikka.shizuku:provider AAR 本该自动合并进来的 <uses-permission> 与 V3_SUPPORT 元数据从未进入 Manifest（只用了裸 jar）。这与 0.1.54 的 ${applicationId} 占位符未替换属于同一类「手搓打包丢配置」问题。Shizuku Manager 也因此不会把本应用列入「应用管理」授权列表。

五、请这样验证

  1. 安装 Cyber-Hub-Manager-0.1.59-r5.apk（覆盖安装即可，不必卸载）。
  2. 打开 Shizuku 应用 → 停止服务 → 重新启动服务。服务端 BinderSender 用 PID_LIST / UID_LIST 记住已推送过的 UID，覆盖安装后必须重启服务才会重新推送；设备无 Root，请确认服务是通过无线调试启动并显示「正在运行」。
  3. 在 Shizuku 的「应用管理」里允许本应用（v3 客户端标记现已声明）。
  4. 从最近任务里划掉本应用（或系统设置里强制停止），重新打开。
  5. 设置 → 启动 → Root / Shizuku 授权 → 诊断提权链路，预期：apiV23Declared: true、v3SupportDeclared: true、shizukuRunning: true、shizukuVersion: 13、shizukuUid: 2000（adb 身份）、elevatedId: uid=2000(shell)…。随后轻点「Shizuku：未授权 · 轻点申请」完成授权。
若重启服务后仍为 false，说明设备侧 Shizuku 服务本身没起来（无线调试每次开机都需重新启动），这不是本应用能修的；此时 apiV23Declared 为 true 可以把两类问题明确区分开。
