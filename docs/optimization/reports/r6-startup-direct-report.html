一、反馈的症状

真机冷启动截图显示：应用打开后先出现一整页启动提示「正在打开您的工作区… / 文件管理器正在加载。」并带一个「重试」按钮，需要等待甚至手动点击才能进入文件管理器。用户明确要求「改一下，直接进入管理器」。

这不是资源加载失败，而是界面结构本身：WebView 渲染的第一帧就是这张提示页，与管理器的双窗格无关。

二、根因

环节原实现后果
app.html<section id="content"> 内写死整页 .bootStatus（含静态 #bootRetry），工具栏副标题为「正在启动…」WebView 首帧必然是提示页
app.js · init()先 await rpc('init') → await refresh() 拉到目录 → 才 renderFiles() 替换成双窗格冷启动 / 授权弹窗等待越久，提示页停留越久
boot.js20 秒 watchdog 超时后 report() 把页面变成错误兜底页慢启动还会额外出现「重试」错误页

因此「直接进入管理器」需要让静态首屏本身就是管理器骨架，并在脚本加载后、任何异步等待之前就把工具栏与底栏补齐；数据返回只是把文件内容填进已有骨架。

三、改动清单

文件改动
app.html删除 .bootStatus 整页提示与 #bootRetry；首屏直接给出 .filepanes 双窗格骨架（左右各一个 .pane + .bootPlaceholder「正在读取文件…」）；副标题改为「文件管理器」；保留 <noscript> 兜底
app.js新增 renderBootFrame()，并让 init() 在第一个 await 之前同步调用它补齐工具栏按钮与底栏（header() + renderFileBottom()）；目录数据随后异步回填；UI_BUILD 更新为 r6，关于页追加版本说明
boot.js移除静态 #bootRetry 绑定；完整保留 20 秒 watchdog 与 report()——脚本真正崩溃 / 加载超时时仍会整页重建出带「重试」（window.location.reload()）的错误兜底页
style.css追加 .bootPlaceholder 轻量占位样式（浅 / 深主题）
tests/startup-direct-check.py新增防回归硬断言，固定「首屏双窗格 / 无提示页与静态重试按钮 / renderBootFrame() 在 await 前调用 / 错误兜底保留 / 占位文案」等 12 项约束，并加入 CI 前端测试步骤
docs/optimization/README.md追加 r6 章节，记录根因、改动、验证与兼容边界
